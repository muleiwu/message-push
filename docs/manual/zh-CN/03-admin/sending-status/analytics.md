# 统计看板

## 用途、路径与前置条件

访问 `/admin/#/analytics`。页面按服务端本地日历时间聚合真实用户任务，管理员测试不计入统计。所有已登录管理员均可只读查看。

![统计看板](../../assets/screenshots/analytics/01-dashboard.png)

## 页面区域与操作

默认展示含今天在内的最近 30 天，可快速切换最近 7 天、30 天或 90 天，也可选择不超过 90 天的自定义范围。应用、通道和消息类型筛选会同时作用于摘要、图表、排行和每日明细。

页面包括：

- 总任务、成功、失败、进行中和任务成功率摘要；
- 每日发送量与任务成功率趋势；
- 待处理、处理中、等待回执、成功和失败状态构成；
- 消息类型构成、应用与通道排行；
- 可用于精确核对图表的每日统计明细。

点击“查询”应用当前筛选；“刷新”按已应用的筛选重新读取。刷新失败时页面会保留上一次成功数据，并显示对应更新时间。

## 字段解释与注意事项

- **总任务**按 `push_tasks` 中的逻辑任务计数。服务商重试或切换产生的多条发送日志不会重复增加总量。
- **进行中**为待处理、处理中和等待回执任务之和。
- **任务成功率**为成功任务数除以已结束任务数，即 `成功 ÷（成功 + 失败）`；尚未结束的任务不进入分母。
- 短信通常在收到成功回执后成为成功，邮件、企业微信和钉钉等渠道可能在服务商接受请求后即成为成功，因此该指标不是统一的终端送达率。
- 统计按任务创建日归档，但展示任务的当前状态。延迟回执到达后，历史日期中的成功数和失败数可能随之收敛。
- 页面显示服务端使用的统计时区。跨时区部署应统一应用与数据库时区，并核对午夜附近的数据边界。

统计接口中的核心字段口径如下：

| 字段 | 口径 |
|---|---|
| `total_count` | 筛选范围内逻辑任务总数。 |
| `success_count` / `failure_count` | 当前状态已经成功 / 失败的终态任务数。 |
| `pending_count` / `processing_count` / `sent_count` | 待处理 / 处理中 / 已提交并等待回执的任务数。 |
| `in_progress_count` | 上述三种进行中状态之和。 |
| `completed_success_rate` | 数值型终态成功率，范围为 0–100；没有终态任务时为 `null`。 |
| `success_rate` | 为兼容旧调用保留的字符串字段，仍按 `成功 ÷ 总任务` 计算；统计看板不使用该字段。 |
