## Design Context

### Users

The admin console serves a mixed audience of message-operations staff and developers. They need to configure provider resources, assemble a sendable channel, verify it with a real test, connect an application, and inspect delivery outcomes without first understanding the database model.

### Brand Personality

Professional, clear, and trustworthy, with enough guidance to make a complex delivery pipeline feel manageable. The interface should create confidence and calm rather than urgency or novelty.

### Aesthetic Direction

Use a refined cloud-control-plane aesthetic built on the existing blue and deep-slate identity. Support light, dark, and automatic themes with the existing design tokens. Prefer precise hierarchy, restrained surfaces, readable status language, and purposeful relationship lines over gradients, oversized hero treatments, or repeated metric-card grids.

### Design Principles

1. Organize around the user's workflow: configure, test, send, and inspect results.
2. Keep the setup guide permanently available; completed steps become quieter but never disappear.
3. Show the real dependency graph: system templates and provider resources converge at the sending channel, while application access joins only for production API sending.
4. Every status must explain the next useful action in plain language; reveal mappings, weights, and failover details progressively.
5. Use semantic theme tokens, keyboard-accessible controls, text-plus-icon states, responsive layouts, and reduced-motion support.
